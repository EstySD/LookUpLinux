# Phase 5.1 Plan 02: Contextual Provider and Safe Persistence Summary

**Occurrence-specific Russian meanings now have a strict text-only provider, bounded cache and exact token/context/span persistence without a second search count.**

## Accomplishments

- Frozen `ContextRequest(context,start,end,word,provider,target)` rejects invalid/bool offsets, wrong source identity, overlong/unsafe context and control characters before network/cache access. `ContextResult(meaning,provider)` remains a plain-text value.
- `translate_context` sends one escaped source with exactly the selected occurrence marked, through the existing fixed-host TLS transport and finite deadline. It accepts only one balanced literal `<b>` span in bounded JSON translation output, with a nonempty bounded Russian value; malformed markup, HTML attributes/comments/declarations, wrong language and echoed English are refused with private fixed error reasons.
- `cache_get/cache_put` validate untrusted payloads, key all six request identity dimensions and cap cache growth at 1000 entries. Legacy translation kinds and their table remain unchanged.
- Additive migration `_v3` preserves old words/counters/translations/meta and adds contextual identity/value columns plus a separate cache. Existing migration snapshot/rollback machinery is retained.
- `upsert_word(..., context_span=None, context_token=None)` still counts once and clears the preceding contextual value. When a span exists, it preserves exact context bytes and requires a nonempty event token.
- `enrich_word_context` updates only a matching word/token/context/start/end row. It changes neither count nor search times and refuses stale, deleted or recreated events. `get_word_context` returns a single snapshot with dictionary translation retained as fallback.
