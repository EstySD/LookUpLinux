## Critical Issues

### CR-01: Terminal punctuation prevents wrapped-word recovery

**Classification:** BLOCKER
**Disposition:** RESOLVED. The join now validates the normalized continuation with `_key(unit)`, allowing retained terminal punctuation while keeping the complete joined source span. Added regression covers both halves with a period and closing quote; an independent comma-continuation check also passed. Sentence trimming includes the terminator and closing quote.
**File:** `lookup/ocr.py:252`

**Issue:** The cross-line join requires `_fragment(unit)`, whose alphabetic-only check rejects normal terminal punctuation. For `paragraph('They showed the trans-', 'lation.')`, selecting the first half yields `word='trans'`, and selecting the second yields `word='lation'`. Both return `context='They showed the trans-\nlation.'` with `context_complete=True`. Thus a routine sentence-final wrapped word is searched/saved as a fragment and can be sent as the selected contextual word, despite a confident full-sentence flag. Existing wrap tests only use an unpunctuated second half.

**Fix:** Validate the alphabetic continuation separately from permissible trailing punctuation, preserve that punctuation in assembled source, and map both source halves to the complete joined word span. If joining is genuinely ambiguous, refuse the contextual span/complete flag rather than treating a half-word as complete. Add regressions selecting both halves with a period and with a comma before following words.

**Reproduction:**

```python
from tests.test_ocr import paragraph, ContextTests
case = ContextTests()
for token in ('trans-', 'lation.'):
    selected = case.select(paragraph('They showed the trans-', 'lation.'), token)
    print(selected.word, selected.context, selected.context_complete)
# trans / lation; raw hyphen and newline retained; True
```

### CR-02: Earlier completed sentences consume the selected sentence's line budget

**Classification:** BLOCKER
**Disposition:** RESOLVED. `_continues` now stops at a reliable preceding sentence terminator while preserving the abbreviation exception. The new four-line regression checks selection near the beginning, middle and end of the target sentence, excluding the completed preceding sentence.
**File:** `lookup/ocr.py:237`

**Issue:** Context growth always takes a unique predecessor before a successor, even when that predecessor ends a different complete sentence. The four-line cap therefore applies before sentence trimming and can discard a reliable fourth line of the selected sentence. Reproduction with one completed preceding line followed by a four-line target sentence returns only three target lines and `context_complete=False`. The data is available, its boundary is unambiguous, and CAPT-05 explicitly requires four-line sentences and multiple sentences in a block; the current two-sentence test does not combine those conditions.

**Fix:** Respect reliable sentence boundaries while growing the neighborhood, or budget the four recovered lines around the selected sentence rather than spending them on completed neighboring sentences. Preserve source identity mappings and conservative abbreviation handling. Add a regression with a four-line selected sentence after a completed sentence, selecting multiple positions within the target.

**Reproduction:**

```python
from tests.test_ocr import paragraph, ContextTests
selected = ContextTests().select(paragraph(
    'We slept.',
    'They sat on the bank',
    'of the river and watched',
    'the ducks swim past',
    'until the sun set.'), 'bank')
print(selected.context, selected.context_complete)
# Missing 'until the sun set.'; False
```
