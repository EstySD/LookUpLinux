## Resolved Timing Method

**Selected method:** one guest CLOCK_MONOTONIC clock, with acceptance start taken ONLY from the completing key-down's KERNEL evdev event timestamp after EVIOCSCLOCKID(CLOCK_MONOTONIC) is successfully set and the event timestamp domain is verified on that descriptor. A bounded privileged observer in the owned VM passively reads only the configured chord plus matched release/sequence; no EVIOCGRAB, shortcut registration or unrelated key logging. Userspace monotonic receipt time is diagnostic delivery/poll information ONLY and NEVER an acceptance origin: delayed receipt may occur after Trigger and must not shorten measured latency. The visible-capture end uses the same guest CLOCK_MONOTONIC domain. Discover correct virtual keyboard through sysfs, do not assume event0. Stop observer before leaving the owned session. [CITED: https://docs.kernel.org/input/event-codes.html and https://docs.kernel.org/input/input.html; corrected execution prescription]

Capture guest desktop/framebuffer repeatedly around useful-ready presentation, with start/end monotonic brackets. Accept end only when the actual captured frame contains this request's useful word/article, not loading/error/previous card. Keep first-visible capture end as a conservative upper-bound latency, last-not-visible/first-visible bracket and sampling uncertainty. A Qt paint/queued callback is useful additional telemetry, not actual compositor proof. Capture observation has overhead: predeclare cadence (e.g. 50–100ms plus capture duration), record it, and do not subtract estimated latency to pass. Correlate by (PID, process start, request ID, input sequence), because IDs restart across cold daemons. [VERIFIED: current ready/GUI semantics; selected observation contract]

If EVIOCSCLOCKID support or the KERNEL event timestamp domain cannot be verified, HOST fallback is mandatory: timestamp host monotonic BEFORE physical VBox input dispatch and use the SAME host clock at actual first-useful framebuffer capture end as the conservative end-to-end upper bound; report host scheduling/capture overhead separately without subtracting it. Never substitute userspace evdev receipt time or subtract unrelated host/guest clocks. Behavioral oracle tests must delay receipt while holding kernel event/frame timestamps fixed: latency and threshold result cannot improve, and a receipt-origin record must be rejected. Supplement daemon LOOKUP_TIMING numeric stage output: dispatch-to-Trigger, queued/capture/OCR/dictionary/cache/network/first-useful/meaning-ready where actually measured; no text/URLs/tokens.
