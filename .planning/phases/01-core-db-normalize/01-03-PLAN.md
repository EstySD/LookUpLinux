  <action>
Create the worker and the tests. All multiprocessing uses `multiprocessing.get_context("spawn")` explicitly (the only start method on Windows, also valid on Linux) and the worker lives in an importable module, never a lambda, nested function or test-module local (Pitfall 5).

`tests/_workers.py` - top-level function `child(path, barrier, queue, index)`: wrap everything in try/except. Body: `barrier.wait(timeout=30)` so all workers hit `open_store` at the same instant; `conn = open_store(Path(path))`; `count = upsert_word(conn, "run", translation="бежать", context="context %d" % index)`; close the connection in a `finally`; `queue.put(("ok", count))`. On any exception put `("err", type(exc).__name__ + ": " + str(exc))` instead, never re-raise (the parent inspects results). The module defines no import-time side effects and does not print.

`tests/test_concurrency.py` - class `ConcurrentWriterTests(unittest.TestCase)`; `setUp` calls `make_tempdir`. Helper `_run_writers(path, n=10, reader=None)`: `ctx = multiprocessing.get_context("spawn")`, `barrier = ctx.Barrier(n)`, `queue = ctx.Queue()`, create and start `n` `ctx.Process(target=_workers.child, args=(str(path), barrier, queue, i))` objects; register a cleanup that terminates any still-alive process; when `reader` (an open `sqlite3` connection) is given, loop while any process is alive running `SELECT count FROM words WHERE word = 'run'` and record every result (`None` before the first insert is allowed), pausing 10 ms between reads; then collect `n` results with `queue.get(timeout=60)`, `join(30)` every process and return `(results, reader_values)`.
- `test_ten_writers_on_precreated_db` (SC3, DATA-01): parent calls `open_store(path)` and closes it, then opens a separate read connection (closed via `addCleanup`), runs `_run_writers(path, reader=conn)`. Assert: no result is an `err` (assert on the list of errors so a failure prints them); `sorted(counts) == list(range(1, 11))`; reader never raised and every value it saw is `None` or an int between 1 and 10 and the sequence is non-decreasing when `None` is read as 0 (a reader SELECT completed while writers ran); a fresh `open_store(path)` shows exactly one `words` row, count 10, translation `бежать`, non-empty context, `PRAGMA journal_mode` equal to `wal`; close that connection.
- `test_ten_writers_on_fresh_db` (SC3, D-20 regression): for each of 3 rounds (`subTest`), pick a database path inside the temp dir that does not exist (assert `not path.exists()` first), run `_run_writers(path)` with no pre-creation, and assert the same invariants (no errors, counts exactly 1..10, one row, count 10). The explicit absence of any `database is locked` text in the results is part of the first assertion.
`lookup/store.py` is a CONDITIONAL edit: leave it untouched when the tests pass as written. If a failure exposes a real defect, make the minimal fix in `lookup/store.py`, record it as a deviation in the SUMMARY, and re-run the full plan 01-02 suite (`python -m unittest tests.test_store tests.test_paths tests.test_migrations`) which must still exit 0. Fix (for example the `_ensure_wal` retry or the `BEGIN IMMEDIATE` handling) and keep the test as written; never lower the worker count, add sleeps to the worker, or catch and ignore lock errors in the test. Close every connection before the temp dir is cleaned up (Pitfall 6).
