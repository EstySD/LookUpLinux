<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command line and stdin of the user to program | text to look up and the context string |
| program to terminal and logs | stdout/stderr are shown to the user and may be captured by shell history or logging tools |
| environment variables to file paths | LOOKUP_* variables select databases, dictionaries, config and cache |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-02-40 | Information disclosure | stderr lines and tracebacks echoing exception messages that carry the query | high | mitigate | The CLI prints only exception type names and fixed Russian reason texts to stderr; a catch-all converts unexpected errors into a one-line message; behavioural privacy test asserts the sentinel is absent |
| T-02-41 | Information disclosure | print or logging calls inside library modules (V7) | high | mitigate | AST-based test fails the build if any `lookup/*.py` other than `__main__.py` calls print, imports logging or warnings, or writes to sys.stdout/sys.stderr |
| T-02-42 | Denial of service | very long argument or context strings | low | accept | Online path truncates to 1000 characters (plan 04/09); local classification is linear; no additional limit needed for a local single-user tool |
| T-02-43 | Tampering | LOOKUP_DB, LOOKUP_DICTS, LOOKUP_CONFIG, LOOKUP_CACHE override paths | low | accept | Documented test and override hooks (D-01, Phase 1 D-11); the user's own environment is not a trust boundary against the user |
</threat_model>
