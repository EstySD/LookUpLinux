<objective>
Implement the StarDict reader (the format of the default Mueller 7 dictionary) with strict per-entry validation, random access into dictzip data, plain-text field conversion and the Mueller article parser that produces transcription, parts of speech and the "от X" pointer flags that base-form search needs.

Purpose: TRAN-01 (a StarDict dictionary dropped into the folder just works, transcription and parts of speech are separate fields) and TRAN-04 (pointer articles such as `ran` = "_p. от run 2" must be recognisable, D-28).
Output: `lookup/stardict.py`, `tests/_stardict_writer.py`, `tests/test_stardict.py`.
</objective>

  <action>
Create `lookup/stardict.py` (stdlib only; module docstring repeats the V7 rule: no printing, no logging, DictError reasons never contain file content).

`open_stardict(ifo_path)`:
- Read the `.ifo` (at most `MAX_IFO_BYTES`, UTF-8, tolerant of BOM and CRLF): first line must be `StarDict's dict ifo file`, then `key=value` lines. Use `bookname` as `name` (fall back to the file stem). Honour `version` and `idxoffsetbits`: 32 (default) or 64, and 64 only with version 3.0.0, otherwise `DictError("unsupported")`. Keep `sametypesequence` (string or None). Never trust `wordcount` or `idxfilesize` (D-33).
- Find sibling files by the exact same basename: index `X.idx` or `X.idx.gz` (prefer plain), data `X.dict` (prefer) or `X.dict.dz`, optional `X.syn`. Dotfiles and every other suffix are never considered (Pitfall 4). Missing index or data raises `DictError("missing_files")`.
- Read the index (gzip via `gzip.open(...).read(MAX_IDX_BYTES + 1)` for `.gz`; reject larger with `DictError("too_large")`). Parse entries sequentially: headword up to NUL (UTF-8, errors replaced), then offset (4 or 8 bytes big-endian) and size (4 bytes big-endian). Data length is the plain file size or `DictzipFile.size`. Skip and count an entry whose headword is empty, whose size is 0 or above `MAX_ARTICLE_BYTES`, or whose `offset + size` exceeds the data length. If the index ends inside an entry, stop and count one skipped. Entry numbers for `.syn` are positions over all parsed entries, valid or skipped. Build `folded_key -> [entry numbers]` with `fold_key` (valid entries only). `.syn`: records of NUL-terminated word plus 4-byte big-endian entry number; add folded synonym keys pointing at the referenced valid entry, ignore out-of-range numbers, cap the file at `MAX_IDX_BYTES`.
- Data access: keep one open file handle (plain `.dict`, seek and read) or one `DictzipFile` (`.dict.dz`), opened once (D-08). Any `DictzipError` while opening becomes `DictError("corrupt")`.
- Class `StarDictDictionary` exposes the shared contract listed in the artifacts. `lookup(key)` builds an `Article` per entry number (deduplicated, in index order); a read or decode failure for one entry skips that entry. `close()` releases the handle.

Field decoding (D-05, D-06): split the entry data using `sametypesequence` when present (every field but the last is NUL-terminated if lowercase or 4-byte-length-prefixed if uppercase; the last field takes the rest), or the per-field type byte layout when absent. Convert: m and l and w to text; t and y to transcription; x (XDXF), h, g and k through `html_to_text`, taking the first `tr` element of an XDXF fragment as transcription when no t or y field exists; r, W, P and unknown types are ignored. Join the non-empty texts with a newline and pass the result through `clean_text`. Headword in the Article is the dictionary's own spelling from the index. Mueller-style parsing of m text is added in Task 2; in this task `senses` is empty and `transcription` comes only from t, y and tr.

Create `tests/_stardict_writer.py` with `write_stardict` (parameters in the artifacts list). `entries` is a list of `(headword, data)` where data is bytes (raw field layout) or str (UTF-8); with `sametypesequence` set the writer concatenates data as given, otherwise it expects pre-built field layout bytes. It writes `.ifo` (with wordcount deliberately computed from `entries`, overridable), `.idx` or `.idx.gz`, `.dict` and/or `.dict.dz` (via `make_dictzip`), optional `.syn`, and appends `extra_idx` raw index records (headword bytes, offset, size) so tests can build Mueller-like invalid entries. Write `tests/test_stardict.py` classes `StarDictReaderTests`, `StarDictValidationTests`, `FieldTypeTests`; every dictionary is closed through `addCleanup` before the temp dir is removed (Windows).

  <action>
Add `parse_mueller(text) -> MuellerParts` to `lookup/stardict.py` and use it for every field of type m (D-06). Pure function, no side effects, scans at most the first 20000 characters of the text and applies the pointer test to the first 600 characters only (bounded work against hostile input, T-02-20); regular expressions must not nest unbounded quantifiers.
- Transcription: the text of a leading `[...]` group (after optional whitespace), stripped; otherwise None.
- Parts of speech: tokens `_pos.` where pos is in the whitelist n, a, v, adv, pl, p, p-p, pres-p, attr, comp, sup, pred, predic, prep, conj, pron, num, int, interj, art, aux; other `_label.` tokens (Cyrillic or Latin usage labels) are not parts of speech. Values for a part of speech are the text up to the next whitelisted token, split on sense markers of the form `N>` (digit or Cyrillic or Latin letter, then `>`) and numbering `N.`; each value is stripped, empty values and values that are only an "от X" pointer are dropped, each is cut at 80 characters, at most 5 per part of speech; when no markers exist the segment is a single value. Remove `_I`, `_II` homograph markers before splitting. `senses` is the tuple of `(pos, values)` in order of appearance (best effort; the full text always stays in `Article.text`).
- Pointer: anchored at the start of the article (after an optional transcription group and an optional numbering `1.`), a token `_label.` followed by `от` and a target of one to three words made of letters, apostrophes and hyphens (digits end the target, so "от run 2" targets "run"). That match sets `form_of` (the target as written). `pointer_only` is True when nothing but an optional homograph number, whitespace and `;` or `.` follows the target. A pointer that is not at the start (inside parentheses, after another part of speech, in a later homograph block) is NOT a pointer (so better, worse, data and news stay ordinary articles, D-28). No other dictionary format sets these fields.
Wire it in: the Article built from an m field takes `transcription` (when no t or y field supplied one), `senses`, `form_of`, and `pointer_only` (True only when the entry consists of that single m field). Add class `MuellerParseTests` and the integration test to `tests/test_stardict.py`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dictionary files to reader | .ifo, .idx, .syn, .dict and .dict.dz are user-supplied; every offset, size and count in them is untrusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-18 | Denial of service / tampering | index entries with out-of-range offsets or absurd sizes (the real Mueller index has one) | high | mitigate | Per-entry validation against the real data length and `MAX_ARTICLE_BYTES`; invalid entries skipped and counted, never allocated or sliced; `wordcount` ignored; tests mirror the Mueller defect |
| T-02-19 | Denial of service | huge or gzip-bomb index or syn file | high | mitigate | Index and syn read through a bounded `read(MAX_IDX_BYTES + 1)` and rejected when larger; ifo capped at 64 KiB; dictzip chunks bounded by plan 02 |

| T-02-21 | Tampering | markup injection through x, h, g, k fields reaching the UI | medium | mitigate | All markup types go through `html_to_text` (plain text only); `Article.text` never holds markup |
