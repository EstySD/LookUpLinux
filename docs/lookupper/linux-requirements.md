# Требования к самостоятельному Linux-аналогу

Дата: 2026-10-27. Основание — принятые требования LookUpLinux и
[исследование оригинала](architecture.md). Документ уточняет поведение
и приёмку; он не отмечает новые задачи выполненными. Расширение v1 от
2026-10-27 по указанию Дениса отражено в REQUIREMENTS и ROADMAP:
CAPT-05/TRAN-06 — Phase 5.1, GAME-01 — Phase 8.

## 1. Цель и объём

Пользователь на Arch Linux с KDE Plasma 6 Wayland получает значение
английского слова на русском, оставаясь в текущем приложении, и сохраняет
историю с контекстом. Стек проекта: Python, PyQt6, Tesseract и средства KDE.
Исследование PP-OCR не отменяет уже выбранный OCR.

Идентификаторы ниже взяты из [основного списка требований](../../.planning/REQUIREMENTS.md).
Состояния реализации определяются там и в проверках фаз, а не этим документом.

| Объём | Функции |
| --- | --- |
| Принятый v1 | EN→RU, хоткей, фон/трей, выделение или OCR, StarDict/DSL/MDX, онлайн-фолбэк, многострочный контекст, значение слова по контексту, история, собственное повторение, экспорт CSV/файла для импорта в Anki, настройки, PKGBUILD, диагностика, проверки в реальных полноэкранных играх. |
| Принятый v2 | Произношение, CEFR/синонимы, Yomitan, скриншот сцены, AnkiConnect/Quizlet и другие явно отложенные возможности. |
| За пределами текущего объёма | Все языки оригинала, полноэкранный перевод, локальная LLM, геймпад, зависимость от закрытых шлюзов Lookupper. |

Снимок принятого объёма не превращает интерфейс оригинала в обязательный
дизайн. Наши Meta+Shift+D, Breeze и начальная сортировка по частоте остаются
проектными решениями. Наблюдавшиеся Alt+Q, Fluent и «Сначала новые» — свойства
конкретной установки оригинала.

## 2. Основной сценарий и приёмка

| Требования | Проверяемое поведение Linux-аналога |
| --- | --- |
| TRIG-01, TRIG-03 | Из другого приложения хоткей запускает ровно один поиск в одном фоновом экземпляре; повторный вызов команды не плодит процессы. В трее доступны принятые разделы проекта. |
| CAPT-01, CAPT-02 | Новое допустимое выделение имеет приоритет; повтор того же выделения не перехватывает новый OCR-запрос. Без нового выделения читается изображение монитора с курсором. Это наш контракт, не установленное правило Lookupper. |
| CAPT-01, CAPT-03 | Положение курсора и OCR-боксы относятся к одному изображению в физических пикселях. При масштабе 100%, 125%, 200% выбирается то же слово. Отрицательное начало координат соседнего монитора не обрезается до нуля. |
| CAPT-03 | На слове выбирается оно; в небольшом промежутке допускается ограниченный ближайший поиск; далеко от текста, на мусоре и при низкой уверенности показывается отсутствие результата, без записи в историю. Числовые пороги берутся из проверенной реализации, не выдумываются по снимкам оригинала. |
| CAPT-04 | Проверяются `break out` с курсором над каждой частью, дефисные слова и границы соседних строк. Выбранная фраза не должна захватывать другую строку или соседний текстовый блок. Склейку переноса через две строки сначала проверяем отдельно: поддержка в оригинале не означает готовность нашей реализации. |
| TRAN-01, TRAN-04 | Форма ищется в включённых словарях в заданном порядке; отсутствие формы допускает поиск основы. В карточке различимы исходное `children` и найденное `child`. Отсутствие леммы не должно менять исходное слово на догадку. |
| TRAN-02, TRAN-03 | Нет подходящей статьи либо запрос является фразой — выполняется предусмотренный онлайн-поиск, если он включён. Повторный успешный запрос использует кеш. Ошибка одного источника не превращается в пустую успешную карточку. |
| TRAN-05 | Исходный контекст сохраняется отдельно от перевода. Ошибка перевода контекста не скрывает готовую словарную статью. Пустой контекст не отправляется в сеть. |
| CAPT-05 | Предложение восстанавливается через несколько строк одного блока с обработкой переноса слова. Соседние колонки, подписи и реплики не склеиваются. Неоднозначность оставляет доступный фрагмент без выдуманного продолжения. |
| TRAN-06 | Отдельно выводится русское значение выбранного слова по контексту, в том числе при готовой офлайн-статье. Проверяются разные значения одного слова и выбранное вхождение. Кэш различает контексты и источник; сохранённое значение соответствует сохранённому контексту. Нет сети/надёжного контекста — словарный результат и явный статус. Метод/провайдер выбирается и проверяется в Phase 5.1. |
| GAME-01 | Phase 8 проверяет физический хоткей, реальный захват, OCR, попап поверх игры, закрытие и возврат управления минимум в двух реальных играх. Полноэкранный прогон обязателен, borderless — при наличии. Фиксируются версии, режимы, задержки и ограничения VM; тестовое окно и недоступный режим не засчитываются как успешная игровая проверка. |
| POP-01, POP-05 | Карточка связана с выбранным словом, остаётся в пределах нужного монитора, показывает доступные поля и словарную статью. Отсутствующие IPA/часть речи не заменяются выдуманными значениями. Тема соответствует KDE. |
| TRIG-02 | Более новый запрос заменяет предыдущий. Поздний ответ старого поиска не меняет новую карточку и не создаёт повторную запись. Проверка проводится с намеренно задержанным первым ответом. |
| POP-02, POP-03 | Esc, клик вне окна, потеря фокуса и таймаут закрывают карточку согласно принятому контракту. Каждый вызов даёт результат или понятное состояние ошибки; закрытая карточка не открывается поздним сетевым ответом. |
| DATA-01, DATA-02 | Одно завершённое допустимое событие поиска увеличивает счётчик один раз; нормализованный ключ, исходный контекст и времена сохраняются согласованно. Неудачный захват/OCR не записывает мусор. Окончательная граница «найдено» проверяется на сценариях словаря, сети и ошибок отдельно. |
| DATA-03 | Фраза из 2–4 слов сохраняется одной записью; длинный текст только показывается. Граница проверяется на 1, 2, 4 и 5 словах с пунктуацией. |
| POP-04, LIST-01, LIST-02 | Добавление в учебные карточки — явное действие поверх истории поиска. Список поддерживает поиск, принятые сортировки и удаление. Просмотр истории не увеличивает счётчик поиска. |
| LEARN-01, LEARN-02 | Собственное повторение показывает Again/Hard/Good/Easy и интервалы, хранит состояние после перезапуска. CSV и файл для импорта в Anki переносят слово, перевод и контекст без повреждения Unicode. `.apkg` не становится обязательным только из-за формата оригинала. |
| SET-01, TRIG-04 | Изменения хоткея, словарей/порядка, онлайн-режима, таймаута и автозапуска применяются предсказуемо и переживают перезапуск. Повреждённая настройка не уничтожает остальные. |
| INST-01, INST-02 | Установка и удаление проверяются пакетным менеджером в целевой VM. Диагностика отличает отсутствующий инструмент, недоступный Wayland-сервис, ошибку OCR и сети. |

Правило отмены и защита от поздних результатов — уточнение TRIG-02,
а не измеренное поведение оригинала. Автосохранение оригинала не отменяет
наше DATA-01: историю LookUpLinux ведём по принятому контракту, учебную
карточку создаём по POP-04.

## 3. Минимальный контракт данных

Это проектное разделение ответственности. Оно не предписывает новый набор
классов, таблиц или публичный API: существующие структуры переиспользуются.

| Передаваемые данные | Инвариант |
| --- | --- |
| Событие поиска | Имеет собственную идентичность и время; режим выделения/OCR различим. |
| Кадр | Размер изображения, положение курсора в нём и преобразование координат принадлежат одному захвату. Ошибка преобразования не маскируется ближайшим словом. |
| Выбранный текст | Исходная форма, бокс слова, контекст и уверенность отделены от нормализованного ключа. |
| Результат | Источник и статус отделены от текста перевода; словарная форма может отсутствовать. Несколько статей сохраняют порядок словарей. |
| Запись истории | Нормализованный ключ, перевод, контекст, счётчик, первое/последнее время. Схема оригинала не копируется целиком. |
| Учебная карточка | Отдельное состояние повторения и выбранный контекст; удаление записи/карточки не должно молча ломать связанное состояние. |

До расширения v1 контекстом была распознанная строка. По указанию Дениса
от 2026-10-27 CAPT-05 требует предложение через несколько строк одного блока;
произвольные соседние абзацы не объединяются. TRAN-06 добавляет отдельное
значение слова по этому контексту. Снимок сцены остаётся в v2. Завершённые
фазы 1–5 не переотмечаются: новая реализация и приёмка принадлежат Phase 5.1.

## 4. Режимы отказа

| Условие | Ожидаемый результат |
| --- | --- |
| Недоступен захват или курсор | Объяснение проблемы платформы, без ложного «слово не найдено». |
| Пустой кадр, нет близкого слова, низкая уверенность | «Не найдено»; история не меняется. |
| Один словарь повреждён | Остальные источники работают; причина доступна диагностике. |
| Сеть выключена пользователем | Офлайн-результат доступен, сетевые запросы отсутствуют. |
| Сеть отсутствует или истёк лимит ожидания | Готовая офлайн-часть остаётся; ошибка относится к конкретному онлайн-результату. |
| Не удалось сохранить данные | Пользователь видит результат поиска и отдельную ошибку сохранения; счётчик не сообщает ложный успех. |
| Новый хоткей или закрытие окна во время запроса | Старый ответ не подменяет актуальное состояние. |

## 5. Как измерять скорость

PERF-01 сохраняется: медиана «хоткей → полезная карточка» не более 1,5 с
в VM Дениса. Пустая рамка или индикатор загрузки не засчитываются как результат.
Отдельно фиксируются холодный/тёплый запуск и офлайн/онлайн-сценарии;
набор и распределение замеров утверждаются при проверке производительности
в Phase 8, без подмены исходного требования.

Журнал замера содержит длительности захвата, OCR, выбора слова, словаря,
онлайн-ответа и показа. OCR на готовом Breeze-изображении — отдельная метрика,
она не доказывает задержку полного сценария в игре или VM.

Семисекундная пауза в исследовательском Windows-скрипте задаёт момент
наблюдения; это не измерение времени готовности Lookupper.

## 6. Связь с текущим проектом

| Область | Как использовать исследование |
| --- | --- |
| Фазы 1–3: данные, словари, OCR изображения | Сохранить проверенные контракты. Новые наблюдения использовать как дополнительные кейсы, а не объявлять прежние проверки недействительными. |
| Фаза 4: платформа и захват | Приоритет — одна сцена/одни координаты, масштабирование, текущий монитор, оверлей и фокус в VM. Текущий код спайка может меняться параллельно; наличие файла не означает готовность фазы. |
| Фаза 5: склейка сценария | Явно отделить выбор текста, поиск, отрисовку, закрытие и отмену. Проверить ошибки и поздние ответы до полировки вида. |
| Фаза 5.1: расширение v1 | Реализовать и проверить CAPT-05/TRAN-06 до библиотеки/карточек: многострочное предложение, контекстное значение, кэш, сохранение, статусы и отмена. |
| Фаза 6: история и обучение | Разделить повторный поиск, просмотр и создание учебной карточки. Выбрать и проверить собственное расписание повторения. |
| Фазы 7–8: настройки, упаковка, проверка | Проверять целую установку и полный пользовательский маршрут, включая отказ одного из компонентов. |

## 7. Что исследовать до требования полной совместимости

В [реестре вопросов](evidence.md#следующие-проверки) отмечены неподтверждённые
правила границ слов, абзацев, ручного выделения, повторных вызовов, сохранения
и экспорта. Пока они открыты, корректная цель — сопоставимый полезный сценарий
в принятом объёме, без заявления о полном совпадении поведения.
