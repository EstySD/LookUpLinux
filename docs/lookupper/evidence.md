# Доказательства, результаты и следующие проверки

Исследование Lookupper Windows 2.0.6.0. Сводка от 2026-10-26.
Все runtime-наблюдения выполнены агентом; это не ручная приёмка пользователем.

## Правила чтения

Присутствие файла доказывает его наличие, а не использование при каждом
поиске. Строка с именем функции не является трассировкой. Заявление автора
не заменяет эксперимент. Наличие кнопки экспорта не доказывает корректность
импортированного файла. Число процедур в Ghidra не означает восстановление
всего исходного кода.

Идентичность исследованного EXE:
`16af03f18ddc75547683895c2d59bc25d053a311626710b51aaebe9547c7d5e8`.
Версия и SHA-256 связывают нативные Evidence с установленной сборкой;
веб-документация может описывать другую конфигурацию или старую версию.

## Реальные проверки 2026-10-26

### W01: структура интерфейса

Lookupper запущен через установленный AppUserModelID. Наблюдатель обращался
к окнам процесса Lookupper средствами Windows UI Automation, без REA-native-UI
инструментов, рассчитанных в этой конфигурации на другую платформу.

Прочитаны структурные элементы разделов «Слова», «Настройки», «Словари».
Не сохранялись существующие слова пользователя, значения редактируемых полей,
данные аккаунта и названия его игровых профилей. Переключение вкладок
не проверяло поиск, экспорт или импорт словарей.

### W02: управляемая сцена

Исходный текст: `The children watched the bright river.`
Белый фон, чёрный Arial 26; отдельное тестовое окно без выделения текста.
Язык распознавания в текущей установке — английский.

1. Прочитано исходное состояние автосохранения `On`.
2. Автосохранение временно выключено, состояние `Off` проверено.
3. В отдельном процессе открыто тестовое окно; контроллер проверил фокус.
4. Курсор поставлен в центр `children`, отправлен существующий Alt+Q.
5. Через заданную паузу прочитан UIA и сделан снимок области тестовой сцены.
6. Оверлей закрыт через Esc; сценарий повторён для `bright`.
7. Тестовое окно закрыто, автосохранение восстановлено; проверено `On`.

| Наблюдение | Вывод |
| --- | --- |
| На первом снимке выделено `children`, заголовок — `child`, есть пометка множественного числа. | Исходная и словарная формы различаются в видимом результате. Место лемматизации не определено. |
| На втором выделено `bright`, показан перевод «яркий». | Последовательный новый вызов после Esc может выбирать другое слово той же сцены. |
| Обе карточки показывают перевод исходного предложения. | Слово обрабатывается вместе с контекстом, а не только изолированно. Границы многострочного контекста не установлены. |
| Видны секции контекстного перевода и Looktionary. | Карточка объединяет несколько видов результата. Это не доказательство конкретного порядка запросов. |
| Есть кнопки контекста и сохранения слова. | Действия доступны; ручное сохранение и изменение библиотеки этим тестом не проверялись. |

`observation_after_ms` в JSON — пауза около семи секунд до наблюдения.
Из неё нельзя получить задержку первого результата или сравнение скорости
с Tesseract. Фиксации запросов/ответов и нативной трассировки не было.

Проверочный скрипт использует отдельные процессы для сцены и наблюдателя,
публикует координаты центров слов, задаёт DPI-контекст и не посылает хоткей,
пока передний план не принадлежит тестовому окну. Восстановление автосохранения
выполняется в `finally`. Скрипты — вспомогательные материалы исследования,
а не часть Linux-приложения.

Предыдущие попытки сохранены отдельно: один контроллер остановился из-за
отсутствия фокуса, другой прогон не подтвердил наведение при несовпавших
координатах. Они не считаются успешными проверками выбора слова.
Исторические имена PNG переиспользованы последним корректным прогоном;
доказательством снимков служит только актуальный W02.

## Следующие проверки

Для каждого опыта сначала записываются состояние настроек и гипотеза.
Сцена синтетическая; автосохранение выключено с восстановлением.
Отклонение от ожидаемого результата не исправляется молча сменой сценария.

| Вопрос | Состояние | Минимальный следующий опыт и сохраняемый результат |
| --- | --- | --- |
| Q01: слово и промежутки | Частично: два точных наведения подтверждены. | Одни и те же боксы: центр слова, край, пробел, точка далеко от текста. Снимки с физическими координатами и выбранным словом/отказом. |
| Q02: выражения и перенос | Не проверено. | `break out`, дефисное слово и перенос на две строки; курсор на каждой части. Отдельно записать, что выделено, что запрошено и какой контекст показан. |
| Q03: границы контекста | Частично: короткая одна строка. | Два предложения в абзаце, перенос строки без конца предложения и два соседних диалога. Сопоставить исходник и раскрытый контекст. |
| Q04: новое выделение | Не проверено для оригинала. | Одно выделение, повтор без изменения, новое слово под курсором. Не считать Linux CAPT-02 описанием оригинала. |
| Q05: повторный вызов/поздний ответ | Не проверено: в W02 был Esc. | Запрос A, затем B до ответа A. Зафиксировать, какая карточка и какой контекст остаются. Сетевая задержка должна задаваться наблюдаемым способом, не угадываться по UI. |
| Q06: запись, дубль, счётчик | Не проверено. | На отдельной тестовой библиотеке: два поиска одной формы, другой контекст, ручное сохранение и удаление. Не использовать рабочую библиотеку для разрушительных опытов. |
| Q07: офлайн и ошибки | Не проверено. | Один доступный офлайн-словарь, отсутствующее слово, отключённый онлайн-режим, повреждённая тестовая копия словаря. Фиксировать частичный результат и отдельную ошибку. |
| Q08: положение и фокус | Частично: оверлей возле двух слов. | Края экрана, два монитора с разным масштабом, потеря фокуса, клик вне, игра в borderless. Без автоматического переноса Windows-настроек заморозки на Linux. |
| Q09: Anki/CSV | Кнопки и схемы подтверждены, файлы не проверены. | Экспорт маленького набора собственных карточек, импорт в отдельный профиль Anki, повторный импорт и проверка Unicode/контекста/дублей. |
| Q10: производительность | Не измерена. | Время первого полезного результата, холодный/тёплый режим, известный источник. Отдельно полный маршрут Linux в целевой VM. |

Точечный нативный разбор оправдан, когда такой опыт оставляет значимую
неоднозначность. Тогда заранее выбираются строковые/ресурсные ориентиры,
функции и вопросы, чтобы за один дорогой импорт получить нужные списки,
псевдокод и ближайшие связи, а не ещё один общий overview.

Приоритет ближайшего исследования — Q01, Q03 и Q08: выбор слова, контекст
и геометрия непосредственно влияют на текущую интеграцию платформы и попапа.
Q05 проверяется при склейке запросов, Q06/Q09 — при истории и экспорте.
Открытый вопрос об оригинале не отменяет уже проверенный собственный контракт
Linux-проекта и не требует переотмечать завершённую фазу.
